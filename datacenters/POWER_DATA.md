# Map power controls and U.S. data-center research

The **Scale all power plants** slider in the EIA layer card multiplies every visible
EIA, WRI, and NACEI marker from 0.25× to 4×. The gear menu shares the same setting.
Choose **Uniform size** there to remove output-based size differences. Settings are
included in saved state and shared URLs.

The OpenStreetMap U.S. layer has the same draw size choices as the Maryland layer:
reported grid demand, published capacity, projected demand, and estimated draw.
Its settings show coverage counts; feature inspection shows MW, scope, date,
confidence, estimation method, evidence basis, and source links. Capacity is not
measured consumption. Unknown values remain missing and use small markers. Counts
refer to mapped features; campus/building overlap prevents a reliable national sum.

The map joins the generated OSM inventory to
`data/data-centers-openstreetmap-world-enrichment.json` by exact OSM type and ID.
The enrichment file is generated by `promote_worldwide_datacenter_enrichment.py`;
do not hand-edit it. An unavailable enrichment file leaves the location layer
usable and reports that power data is unavailable.

## Continue research with Kimi

From the repository root, preview the next 25 identified U.S. facilities without
API calls:

```bash
bash datacenters/scripts/research-us-datacenter-power.sh preview 25
```

Run research, source fetching, claim review, and local promotion:

```bash
bash datacenters/scripts/research-us-datacenter-power.sh run 25
```

The batch size is 1–100. The command uses `.env.kimi`, two research workers, at
least two searches per facility, and at most the primary and retry tiers. Repeating
it resumes from the checkpoint. It writes only local data; deployment is separate.
Priority 1 selects the 300 records with strong identity leads in the current OSM
snapshot. The underlying research CLI supports `--priority 2` or `--priority 3`
for the remaining records after identity review.

Research, audit decisions, and repair/review queues live under
`research/worldwide-datacenters/`. Failed and conflicting claims stay there. Each
non-null number must have field-specific URLs and pass the source and claim audit.
Reviewed operator domains are registered in
`data/international-research-authorities.json` and accepted only for power profiles.
Directories and OSM are discovery leads, not power evidence. Verify domain ownership
before adding an operator, utility, or grid authority to the registry.

Promotion keeps previously approved profiles when a new research attempt fails
review, and replaces them only when the new candidate passes every source and
claim check. Profiles whose OSM identity leaves the base inventory are removed.
Portfolio and availability-zone figures cannot be promoted onto individual map
features.

## Validate changes

```bash
python3 -m pytest -q tests/test_datacenter_draw_controls.py tests/test_worldwide_datacenter_enrichment.py tests/test_kimi_research_quality.py
python3 datacenters/scripts/selenium-draw-controls.py --base-url http://host.docker.internal:8878/datacenters.html
```

The browser probe expects a Selenium Grid on port 4444 and a site reachable from
its browser container. It exercises scaling across all three plant sources, uniform
sizing, URL restoration, reset, draw options, and a real promoted profile in the
rendered map and inspector. Use `--width 390 --height 844` for mobile acceptance.
